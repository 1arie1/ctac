# TtacShallow — worked shallow-embedding proofs

This library collects **worked safety proofs over the *shallow*
embedding** of Tiny TAC (`ttac`) programs. For each example program the
assertion "this program's `assert` is never violated" is stated as a
Lean theorem `shallow_safe` and proved by hand.

Each module is generated by `ttac lean … --no-deep` (which emits one
`Prop` per basic block, `ok_<label>`, meaning "execution from the top of
`<label>` never fails an assert") and then paired with a hand-written
proof. The generated `namespace <Name>.Shallow` block is kept verbatim;
only the `shallow_safe` theorem is authored. Every proof is
**axiom-clean** (`propext`, `Classical.choice`, `Quot.sound` only).

The example programs are distilled from real Certora Solana/EVM
verification targets — proportional share/asset conversions, fixed-point
rounding, ERC4626 accounting — reduced to pure integer arithmetic and
**scrubbed of all client identity** (variables are `a,b,c` / `x,y,TA,TS`
/ …). The `.ttac` sources live in
[`docs/vc/examples/`](../../docs/vc/examples/) (see its
[README](../../docs/vc/examples/README.md) for how to run them through
`ttac stats/vcgen/run`).

## The examples

They trace a **difficulty ladder** — from a fully-automatic one-shot
tactic on the assume-guarded programs, through core-Lean division
lemmas, to an `nlinarith` search, and up to a large multi-block program
whose proof stays linear in its stage count. `z3` is the solve time on
the `ttac vcgen` output (best of 5, z3 4.17.0; also in each file
header). "Needs" is `core` (dependency-free core Lean) or `Mathlib`.

| Example | Source | Blocks | z3 | Proof | Needs |
|---|---|--:|--:|---|---|

| [`Withdrawal`](./Withdrawal.lean) | [`practical_withdrawal_summary`](../../docs/vc/examples/practical_withdrawal_summary.ttac) | 10 | ~6ms | same one-shot (+ `Bool.and_eq_true`) | core |
| [`Monotone`](./Monotone.lean) | [`nla_muldiv_monotone`](../../docs/vc/examples/nla_muldiv_monotone.ttac) | 1 | ~8ms | `Int.ediv_le_ediv ∘ mul_le_mul_of_nonneg_right` (two lemmas) | core |

## Nested (dominator-tree) variants

Three of the examples also exist in the **nested** shallow form
(`ttac lean --nested`): blocks are `let rec` defs inside their
immediate dominator's body instead of top-level defs, so live-ins are
captured lexically ("SSA is functional programming") and parameters
shrink to phi targets only — `FeeWaterfall`'s `ok_stage1` drops from 18
declared parameters to 0. The elaborator lambda-lifts each `let rec`
into a named constant (`ok_entry.ok_join_a.ok_join_b`, nesting-path
qualified), so the merge-point-lemma proof pattern carries over
unchanged; only the `unfold` spellings and capture-order argument
lists differ.

| Nested variant | Flat twin | What it demonstrates |
|---|---|---|
| [`NestedConvertCap`](./NestedConvertCap.lean) | `ConvertCap` | minimal case: `ok_join` keeps only its phi target |
| [`NestedShareBurnU`](./NestedShareBurnU.lean) | `ShareBurnU` | the folded-merge lemma (`join_b_mono`) against a lifted nested constant |
| [`NestedFeeWaterfall`](./NestedFeeWaterfall.lean) | `FeeWaterfall` | zero-parameter stage defs; the linear `safe_stage` chain re-proved verbatim |

## What the ladder shows

- **Assume-guarded programs** (`ShareBurn`, `Withdrawal`) reduce to
  linear reasoning once the boolean skeleton is simplified: every
  nonlinear `mul`/`ediv` is consumed under an `assume`, so `omega`
  abstracts it and a one-shot `unfold; simp; omega` closes the whole
  program.
- **Every genuinely nonlinear obligation defeats `omega` alone** — it
  abstracts the `ediv`/`mul` atoms. The fix is to supply the
  `Int.ediv`/`Int.emod` identities (`mul_ediv_add_emod`, `emod_nonneg`,
  `ediv_le_iff_le_mul`, `ediv_le_ediv`, …), all in core Lean's `Init`,
  and let `omega` finish the linear residue. `Additivity` is the one
  case tight enough (it depends on the division *remainders*) to need
  `nlinarith`, and hence Mathlib.
- **Control flow scales via merge-point lemmas.** For multi-block
  programs, keeping the downstream blocks *folded* and proving one lemma
  about them — parameterized by the semantic precondition — turns the
  proof linear in the CFG instead of exponential in the branches. This
  is how `ShareBurnU` (a 4-way split) and `FeeWaterfall` (a 34-block,
  2⁸-leaf program) stay short.
- **The `z3` and Lean costs scale differently.** On these clean integer
  forms z3 is uniformly fast and its cost tracks program *size*
  (`FeeWaterfall` slowest, ~345ms); the Lean proof for that same
  program is *linear in its stages* by construction. Different curves,
  not a head-to-head winner. (The `nlinarith` and SBF-chunked bv256
  hardness that makes some of these "hard" for z3 in production lives in
  the *encoding*; the distilled integer property is easy for z3.)

## Building

This library is part of the repo's Lean project (`lean/`); open that
directory in VS Code to browse the proofs with the Lean server.

```bash
cd lean
lake build TtacShallow          # nine examples + three nested variants (~2s after Mathlib is cached)
```

`ShareBurn`, `Withdrawal`, `Monotone`, `Superadd`, `Roundtrip`,
`ConvertCap`, `ShareBurnU`, and `FeeWaterfall` are core Lean; only
`Additivity` uses Mathlib (`nlinarith`). To regenerate an embedding from
its source:

```bash
ttac lean docs/vc/examples/nla_muldiv_roundtrip.ttac -o out/rt --no-deep --name Roundtrip
```

`ttac lean` accepts the scalar fragment (`int`/`bool`, loop-free — TAC
has no loops — no use-before-def) and converts dynamic multi-block
definitions to `phi` form automatically, so the `practical_*` and
`nla_*` programs transpile without hand-rewriting their merges.
